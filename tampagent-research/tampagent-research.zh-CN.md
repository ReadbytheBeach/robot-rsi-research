# TAMPAgent 中文调研与机器人 RSI 研究方案

调研日期：2026-11-05（新加坡时间）。本报告根据用户提供的截图定位项目，并阅读公开项目页、其内嵌智能体手册与相关工作官方仓库。未运行机器人实验，也未获得完整论文或系统实现。

**判断：TAMPAgent 值得作为“语言智能体 + 任务与运动规划 + 可检查执行接口”的架构参考；当前公开证据支持任务执行与重试改进，尚不足以证明递归自我改进。**

这里暂将 RSI 理解为 Recursive Self-Improvement（递归自我改进）；这是待用户确认的研究方向解释。

## 2. 它解决什么问题

机器人在陌生、部分可观测的环境里执行“把苹果放进碗里”时，必须同时处理：苹果在哪里、是否被遮挡、要不要先移动其他物体、抓取姿态是否可达、抓住后能否放下。

语言模型可以提出合理解释，却可能生成物理上不可执行的动作。传统 TAMP（任务与运动规划）可检查离散动作和连续几何条件，但通常需要预先描述问题、动作与世界状态。TAMPAgent 让智能体持续构造问题与假设，同时保留规划器对动作执行的检查职责。

它公开描述的位置 belief 会随证据改变表示：未知时的均匀先验 → 带先验的语言假设 → 掩码与 RGB-D 几何估计。此处没有完整论文可核查这些表示之间的数学更新规则，因此不应直接称其为精确贝叶斯推断或最优 POMDP 求解。

## 3. 核心工作循环

1. 智能体根据指令、观测与假设写出目标和对象清单。
2. 规划器给出实例化动作及其前提条件。
3. 智能体提出到达目标的完整动作序列；规划器检查并编译为约束满足问题（CSP）。
4. 感知、抓取生成、逆运动学、运动规划等工具产生带 receipt_id 的证据。
5. 智能体将证据绑定到约束变量；当前步骤通过 admission 检查后，才能取得执行许可。
6. 执行一步，检查结果，通过 completion 证据更新状态，再重新规划。

例如，苹果被企鹅玩偶遮挡时，检测未得到足够几何证据，机器人不能直接抓苹果。智能体改为假设“苹果在企鹅后面”，先移动企鹅，再观察并抓取苹果。

重要细节：系统会编译整个计划，但逐步执行与重新检查。不能据此声称整段未来轨迹已提前得到物理可行性保证。

## 4. 从公开手册看到的工程机制

| 机制 | 公开说明 | 研究意义 |
|---|---|---|
| 执行网关 | 固定路由白名单；智能体不能直接接触底层机器人接口 | 分离提议计划和执行权限 |
| 工具回执 | 回执具有有效期，并绑定会话、机器人状态等信息 | 减少伪造、过期或跨状态复用证据 |
| 执行许可 | 检查通过后发放对应步骤的 grant | 将动作检查落实到实际执行入口 |
| 状态围栏 | 过期 session/revision 等写入会被拒绝 | 防止陈旧计划更新当前状态 |
| 动作后确认 | 分离 admission 与 completion | “允许执行”不等于“执行成功” |
| 失败恢复 | UNKNOWN 状态、锁、持物状态修正与重新观测 | 避免失败后继续沿用错误状态 |

**保证边界：**项目承认工具可能误判，认证的抓取仍会失败。手册还允许智能体在特定条件下，根据新鲜图像通过 assert_custody 登记持物状态。因此，“有签名回执”不能推导出“所有语义事实均被独立测量验证”。

可进一步审查：自由移动窗口的实际检查范围、动态障碍、未建模物体、感知假阳性、持物状态漂移，以及状态变化后证据失效的完整性。

## 5. 作者报告的实验结果

以下均来自项目页，不是本次独立复现结果。各项指标的统计范围不同，应分别理解。

| 指标 | TAMPAgent | CaP | GaP |
|---|---:|---:|---:|
| 九项厨房任务总体成功率，T1–T8、T10 | 77% | 57% | 61% |
| 遮挡/阻挡任务成功率，T3–T8、T10 | 71% | 45% | 50% |
| 未缓存输入 token / 仿真分钟 | 19.3k | 20.3k | 27.4k |
| 输出 token / 仿真分钟 | 1.75k | 1.91k | 2.73k |
| T9 首次成功所需尝试次数 | 3 | 4 | 3 |

- 九项厨房任务每种方法每任务 20 个 episode；T9 使用跨尝试记忆实验，不包含在这九项均值中。
- 总体成功率比 CaP 高 20 个百分点，比 GaP 高 16 个百分点，按页面四舍五入数据计算。
- T1、T2 的开放场景中，三种方法都完成全部 episode，主要差异出现在遮挡或阻挡任务。
- 更大住宅 T11、T12 中，各方法均为 5/5；T13 均为 4/5。该小样本没有显示 TAMPAgent 的优势。
- 项目报告掉落/场景破坏失败次数分别为 13、26、14；超时次数分别为 28、51、56。这些是 episode 级失败计数，不能作为每次动作风险率。
- 网站声明 RB-Y1 使用 GPT-6-Astra / low reasoning，G1 使用 GPT-5.6 Sol / medium reasoning。这里只记录作者配置；本次未核实这些模型的外部可用性或复现接口。
- 真实机器人展示涉及 RB-Y1 和 Unitree G1，但公开材料不足以推导可靠的真实机器人总体成功率。
- 作者报告机器人在超过 90% 的 episode 时间内等待智能体推理。这表明墙钟耗时是关键瓶颈。

### 结果解读限制

1. 没有公开原始数据、随机种子和置信区间供本次重新分析。
2. 页面未提供足够的组件消融，无法隔离收益究竟来自约束图、提示词、网关、状态记录还是失败反馈。
3. token/仿真分钟不是每成功任务的总费用，也不是墙钟时间。输入数据还只包含未缓存输入，不能直接换算完整账单。
4. GaP 在这里指作者描述的工具图生成与审查基线；本次没有核实其独立论文与完整实现。
5. 真实演示证明存在可展示的运行案例，不能替代覆盖多任务、多种子的统计评测。

## 7. 它是否已经实现 RSI？

建议把四种能力分别评测：

1. **任务内适应：**观察、失败、重新规划；TAMPAgent 有公开案例。
2. **跨尝试记忆：**保留文字经验，下次更快成功；T9 提供有限例证。
3. **持久能力改进：**生成或改进技能，在未见任务上复用；当前公开材料不足以证明。
4. **改进机制自身的改进：**系统修改其技能搜索、课程设计或经验提炼方法，并在多轮迭代后优于固定改进器；这是本研究可采用的更严格 RSI 判据，当前材料未证明。

RSI 不必依赖基础模型权重更新；但同一任务重试更快，也不能单独证明 RSI。要观察持久更新、独立测试泛化，并比较改进机制是否随着迭代变得更有效。

## 8. 推荐研究题目

**约束反馈驱动的机器人技能自我改进：从失败回执到可迁移的工具组合。**

核心问题：在基础模型和执行检查器固定的条件下，智能体能否将约束失败与执行反馈转化为可复用技能，使未见布局和任务的成功率提高、达到目标所需尝试减少，并降低每成功任务的总成本？

第一阶段先验证可迁移的持续改进；只有加入“改进器自身更新”并取得额外证据后，才提出更强的递归自我改进主张。

### 最小实验

- 先用仿真，包含开放抓放、视觉遮挡、几何阻挡、容器访问四类任务。
- 分离训练布局、验证布局和封存测试布局；测试时禁止继续修改技能库，另设在线适应实验。
- 固定基础模型版本、工具、预算和动作检查器。
- 每次失败保存：结构化失败码、上下文、候选计划、动作前后观测、实际结果。
- 学习器只产生待测试的技能组合、检索规则或搜索策略；评测动作仍通过相同执行入口。

| 实验组 | 持久更新 | 用途 |
|---|---|---|
| A 固定智能体 | 无 | 基线 |
| B 文字记忆 | 经验笔记 | 分离纯记忆收益 |
| C 检索经验 | 可检索的结构化失败记录 | 分离检索收益 |
| D 技能学习 | 新增或改进可执行技能组合 | 测试能力积累 |
| E 改进器更新 | 在 D 基础上更新技能搜索/课程策略 | 与 D 比较，测试递归改进假设 |

建议每类任务先以 20 个独立种子作探索性评估，再根据效果大小和方差确定正式样本量；不要事先把该数量宣称为统计充分。

### 主要指标与必要消融

- 主指标：封存测试任务成功率、达到指定成功率所需环境交互次数。
- 成本：每成功任务总 token、工具调用数、真实墙钟时间；单列缓存与未缓存输入。
- 执行质量：掉落、碰撞、超时、状态误判，明确 episode 与动作级分母。
- 迁移：新布局、新物体、目标组合；分开报告任务内适应与测试前已积累能力。
- 消融：无记忆、只有笔记、无失败码、无技能检索、固定改进器。通过离线重放或仿真检查执行约束的作用。
- 防止伪改进：每组相同总模型调用与交互预算；不得把额外重试或更长上下文当成算法收益。
- 防止评测污染：独立评测器给结果，不让学习器修改成功判据；不向学习器暴露封存测试反馈。

### 可证伪条件

如果 D 不优于 B/C，不能声称可执行技能积累优于记忆；如果 E 不优于同预算 D，不能声称递归改进带来额外收益；如果收益只发生在重试过的布局，不能声称未见场景迁移。

## 9. 复现路径与当前缺口

**现在可做：**研究手册、接口、约束证据机制与 T10 记录；建立自己的仿真研究基线。PDDLStream 的示例可作为候选起点，但不是 TAMPAgent 原版复现。

**完整复现仍缺：**论文全文、机器人系统源代码、规划器与工具实现、精确依赖及版本、仿真资产和许可、任务初始化与随机种子、完整基线提示词、模型访问配置、原始评测输出。

建议实施顺序：

1. 先构建冻结模型、固定工具和独立评测器的仿真基线。
2. 加入文字记忆与结构化失败记录，验证跨布局收益。
3. 加入可执行技能组合与回归评测，验证持久能力积累。
4. 最后加入改进器更新，检验严格的 RSI 假设。

本次交付为文献与公开材料调研、架构分析及实验设计；没有声称完成 TAMPAgent 复现或机器人系统环境安装。
